# @anyknown/ui

The design system shared by every AnyKnown product, built with [StyleX](https://stylexjs.com), React 19 and Base UI.

## Structure

- `src/tokens.stylex.ts`: semantic tokens (color, font, type, space, radius, corner, motion, shadow, tone and more). Light is the default; dark follows the OS. **The single source of truth.**
- `src/tokens.css`: the same values as plain CSS variables (`--ak-*`), for consumers that don't use StyleX (desktop references them from Tailwind v4 `@theme`). Import path: `@anyknown/ui/tokens.css`. There is one palette (neutral); light and dark follow the OS, and `data-theme` locks one. **Generated by `pnpm gen:tokens-css`**; don't edit it by hand (`src/tokens-css.test.ts` fails when it is out of sync).
- `src/themes.stylex.ts`: `light` / `dark` themes, for apps with a manual theme switch: `<div {...stylex.props(...light)}>`. **Generated by `pnpm gen:themes`**; don't edit it by hand (`src/themes.test.ts` fails when it is out of sync).
- `src/brand.css`: a bounded vocabulary of about twenty `ak-*` classes for one-off pages with no bundler (reports, proposals, benchmarks). The build inlines the tokens and adds Google Fonts (`scripts/brand-css.mjs`), producing `dist/brand.css` and <https://ui.anyknown.com/brand.css>. The rules are in [DESIGN.md](./DESIGN.md); `pnpm check` fails when the document and the vocabulary disagree.
- `src/scrollbar.css`: custom scrollbars, applied globally. StyleX cannot write `::-webkit-scrollbar` pseudo-elements, so they live in a CSS file.
- `src/components/`: one folder per component: `<Name>.tsx`, an English `README.md` and, in most folders, `<Name>.test.tsx`. Every folder there is a component. The shared decisions are in [components/README.md](./src/components/README.md); the reasoning and the dead ends are in [components/COMPONENTS.md](./src/components/COMPONENTS.md).
- `src/lib/`: shared hooks and helpers: `i18n.tsx` (`LocaleProvider`, `defineStrings`, `useStrings`), `store.ts` (`createStore`, `useStore`), `textLayout.ts` (the optional Pretext engine), plus reduced motion, controllable state, clipboard, diff, `styled` and `reset.control`.
- `docs/guides/`: the guides: [getting started](./docs/guides/getting-started.md), [theming](./docs/guides/theming.md), [state management](./docs/guides/state.md), [accessibility](./docs/guides/accessibility.md), [internationalization](./docs/guides/i18n.md) and [text layout](./docs/guides/text-layout.md).
- `scripts/`: generators and checks. `palette.mjs` computes the colors, `themes.mjs` and `tokens-css.mjs` generate `themes.stylex.ts` and `tokens.css`, and `api-docs.mjs` reads the TypeScript source and writes `site/generated/api.json` (every component's props) and `site/generated/tokens.json` (every token group) for the docs site.
- `playground/`: a demo app. **Not part of the published package.**
- `site/`: the docs site, deployed to Cloudflare Workers. **Not part of the published package.**

## Docs site

<https://ui.anyknown.com> has:

- a page per component at `#/components/<name>`, with its README, demos and a props table generated from the source;
- the guides at `#/guide/<name>`;
- the tokens page at `#/tokens`, with every token and its light and dark value;
- every demo on one page at `#/demo`; `#/demo/<name>` jumps to one. The playground uses the same section ids.

`pnpm site:build` builds the package, then the site, then `llms.txt`.

## Development

```bash
pnpm test         # vitest (jsdom + testing-library)
pnpm check        # turbo run typecheck lint fmt:check design:check (parallel + cached)
pnpm typecheck    # tsc over the library, the playground and the docs site
pnpm build        # dist: ESM + d.ts + tokens.css + scrollbar.css + brand.css
pnpm verify:pack  # build, pack, then resolve every exports-map entry from outside the package
pnpm gen:themes   # regenerate src/themes.stylex.ts from the tokens
pnpm gen:tokens-css  # regenerate src/tokens.css from the tokens
pnpm playground   # http://localhost:5199, every component rendered from the built dist
pnpm site         # http://localhost:5200, the docs site
pnpm site:test    # jsdom smoke tests for the docs site
pnpm site:build   # build the package and the docs site
pnpm site:deploy  # build, then deploy to https://ui.anyknown.com (run wrangler login first)
```

`check`, `test`, `build` and the rest run through [turborepo](https://turborepo.dev) (single-package mode, configured in `turbo.json`). The cache is pushed to the self-hosted remote cache at `https://turbo.anyknown.com` (team `anyknown-ui`). To use the remote cache, export the token:

```bash
export TURBO_TOKEN=<token>   # see turbo-cache-worker/GITHUB-SECRETS.md
```

Without it nothing breaks; turbo falls back to the local cache. The inputs of `build`, `lint`, `typecheck` and `test` in `turbo.json` deliberately exclude `*.md`, so editing docs doesn't rerun them. `site:build` and `site:test` use the default inputs, because the docs site reads those Markdown files.

## Releasing

The package is published as ESM + d.ts. **The StyleX calls stay in the output** and the consumer's bundler compiles them (the standard approach for StyleX libraries).

The version is **set by a git tag**. Push a `v*` tag and `.github/workflows/release.yml` runs the full gate, then publishes. If the tag doesn't match `version` in `package.json`, the workflow fails and nothing is published.

```bash
# 1. Bump version in package.json (semver)
# 2. Commit, tag and push
git commit -am "release: v0.2.0"
git tag v0.2.0
git push origin main --tags
```

CI runs `typecheck / lint / fmt:check / test / site:test`, then `verify:pack`, then `npm publish`. The first five go through the turbo remote cache, so most of them hit what already ran on the PR. `verify:pack` is not cached: its job is to pack a fresh tarball every time and resolve the exports map from outside the package.

Publishing uses **npm trusted publishing (OIDC)**; the repo stores no npm credentials. The trusted publisher on npmjs.com ties `@anyknown/ui` to `anyknown-com/ui` / `release.yml`. CI uses `npm publish`, not `pnpm publish`, because pnpm's OIDC support isn't ready yet ([pnpm#9812](https://github.com/pnpm/pnpm/issues/9812)).

v0.1.0 was published by hand from a local machine: npm can only attach a trusted publisher to a **package that already exists**, so the first version had no way around it. Every version since goes through a tag.

The one thing CI can't check is the visuals. Before a release, open `pnpm playground` and look for visual or motion regressions, then turn on macOS "Reduce motion" and look again.

## Using it in an app

```bash
pnpm add @anyknown/ui @stylexjs/stylex
pnpm add -D @stylexjs/babel-plugin @stylexjs/postcss-plugin postcss @babel/core
```

StyleX needs two passes: Babel turns `stylex.create` into class names, and PostCSS writes the stylesheet. Both must run over `node_modules/@anyknown/ui/dist/**/*.js` as well as your code, with the same `unstable_moduleResolution.rootDir`. The entry CSS needs the bare `@stylex;` directive:

```css
@import "@anyknown/ui/tokens.css";
@import "@anyknown/ui/scrollbar.css";

@stylex;
```

```tsx
import { Button, Card, Text } from "@anyknown/ui"
import { color, space } from "@anyknown/ui/tokens.stylex"
```

Mount `<Toaster />` and `<Dialogs />` once near the root, and wrap the app in `<LocaleProvider locale="en">` for English built-in words (the default is `zh-TW`). Your own styles use the tokens, never raw colors.

The full Vite and PostCSS setup, fonts, Tailwind mapping and a first screen are in [Getting started](./docs/guides/getting-started.md).

## Visual direction: tactile

White paper sheets on a neutral gray desk (OKLCH chroma 0), ink text, an ink primary action and ink links (`#171717`). Blue `signal` is reserved for "the agent is working", focus and progress. Depth comes from light and dark steps and three shadow levels (rest, float, modal), not from borders. Buttons are pills. Headings and body text use Figtree, timelines and data use Geist Mono, and Chinese uses Noto Sans TC (falling back to PingFang TC or Microsoft JhengHei when it isn't installed). The spec is [docs/plans/02-tactile.md](./docs/plans/02-tactile.md). Colors are computed by `scripts/palette.mjs` from five 12-step OKLCH scales (1–2 backgrounds, 3–5 fills, 6–8 borders, 9–10 solids, 11–12 text): to change a color, change the scale, rerun it and paste the output back; never hand-tune a value (see [Theming](./docs/guides/theming.md#change-the-palette)). The earlier woven design language and its ledger palette are archived on the `archive/fiber` branch.

Apps install the fonts themselves:

```bash
pnpm add @fontsource-variable/figtree @fontsource-variable/geist-mono @fontsource-variable/noto-sans-tc
```
