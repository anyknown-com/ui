# Internationalization

Components own a few words of their own: aria-labels, screen-reader prefixes, the text of a button they render. This guide covers how the app picks the language of those words, how to override single words, and how to add a language.

Your own content (titles, messages, button labels you pass in) is never translated by the package. Use your app's i18n library for that.

## Pick the language

Wrap the app in `LocaleProvider`:

```tsx
import { Dialogs, LocaleProvider, Toaster } from "@anyknown/ui"

<LocaleProvider locale="en">
  <App />
  <Toaster />
  <Dialogs />
</LocaleProvider>
```

- Without a provider, the locale is `DEFAULT_LOCALE`, which is `"zh-TW"`: the primary users read Traditional Chinese. **An English app must set `locale="en"`.**
- `locale` is a BCP 47 tag. The package ships words for `"zh-TW"` and `"en"`. Any other tag reads `FALLBACK_LOCALE`, which is `"en"`, for every word its table does not have.
- Portalled popups, dialogs and toasts follow the provider too, because the hosts sit inside it. Mount `<Toaster />` and `<Dialogs />` inside the provider.
- The locale can change at runtime: pass state to `locale` and every built-in word re-renders.

`useLocale()` returns the nearest provider's locale (or `"zh-TW"`), for your own components:

```tsx
import { useLocale } from "@anyknown/ui"

function DateLabel({ date }: { date: Date }) {
  const locale = useLocale()
  return <time dateTime={date.toISOString()}>{date.toLocaleDateString(locale)}</time>
}
```

`LocaleProvider` does not set the `lang` attribute. Set `<html lang>` yourself (`zh-Hant` or `zh-TW` for Traditional Chinese) so screen readers pick the right voice and the browser picks the right CJK glyphs.

## Override single words with `labels`

Every component with built-in words follows the locale and takes a `labels` prop: a partial table of its words. Words you pass win; the rest come from the locale. The table type of each component is exported (`ToastLabels`, `DialogLabels`, `SelectLabels`, …), so a wrong key is a type error.

### Toast

```tsx
import { Toaster } from "@anyknown/ui"

<Toaster labels={{ region: "Activity", dismiss: "Close" }} />
```

`ToastLabels`:

| Key | `en` | `zh-TW` |
| --- | --- | --- |
| `region` | Notifications | 通知 |
| `dismiss` | Dismiss notification | 關閉通知 |
| `success` | Success: | 成功: |
| `danger` | Error: | 錯誤: |
| `warning` | Warning: | 注意: |
| `info` | Info: | 提示: |

`success`, `danger`, `warning` and `info` are visually hidden prefixes that tell a screen reader what kind of toast it is.

### Dialog

`DialogLabels` has two words: `cancel` (Cancel, 取消) for the cancel button of a confirm, and `acknowledge` (OK, 知道了) for the only button of an alert. Set them for every confirm and alert a `<Dialogs>` host renders, or for one `ConfirmDialog`:

```tsx
import { Button, ConfirmDialog, Dialogs, dialog } from "@anyknown/ui"

function App() {
  return (
    <Dialogs labels={{ cancel: "Keep editing", acknowledge: "Got it" }}>
      <ConfirmDialog
        trigger={<Button variant="danger">Discard draft</Button>}
        title="Discard this draft?"
        confirmLabel="Discard draft"
        danger
        onConfirm={discardDraft}
        labels={{ cancel: "Keep draft" }}
      />
    </Dialogs>
  )
}

// One call can still name its own button.
await dialog.confirm({ title: "Leave the call?", confirmLabel: "Leave call", cancelLabel: "Stay" })
```

- For `dialog.confirm` and `dialog.alert`: the call's `cancelLabel` / `confirmLabel`, then the host's `labels`, then the locale.
- For `ConfirmDialog`: its `cancelLabel`, then its `labels`, then the locale. It does not read the host's `labels`.
- `confirmLabel` of a confirm has no default in any language. Name the action.

### Select

Two of `SelectLabels` are functions, because they contain the option or the query:

```tsx
import { Select, SelectItem } from "@anyknown/ui"

function Tags() {
  return (
    <Select
      aria-label="Tags"
      multiple
      defaultValue={[]}
      labels={{
        placeholder: "Pick tags…",
        searchPlaceholder: "Find a tag…",
        searchLabel: "Find a tag",
        remove: (tag) => `Remove tag ${tag}`,
        empty: (query) => `No tag matches “${query}”.`,
      }}
    >
      <SelectItem value="work">Work</SelectItem>
      <SelectItem value="home">Home</SelectItem>
    </Select>
  )
}
```

`placeholder`, `searchPlaceholder`, `searchLabel` and `emptyLabel` also exist as props, and a prop wins over `labels`.

### CallBar

`CallBarLabels` has one word per call status (`listening`, `user-speaking`, `transcribing`, `holding`, `thinking`, `speaking`, `interrupted`), plus `muted`, the group name `call`, and the button names `mute` and `hangUp`. There is no `unmute`: the mute button keeps the name `mute` and reports its state with `aria-pressed`, so a screen reader says "Mute, pressed".

```tsx
import { CallBar } from "@anyknown/ui"

function Call({ muted, setMuted, hangUp }: { muted: boolean; setMuted: (m: boolean) => void; hangUp: () => void }) {
  return (
    <CallBar
      status="listening"
      seconds={42}
      muted={muted}
      onMute={setMuted}
      onHangUp={hangUp}
      labels={{ listening: "Connected", mute: "Microphone off", hangUp: "End call" }}
    />
  )
}
```

## Which components follow the locale

All of them. Every built-in word in `src/components` is declared through `defineStrings`; none is hard-coded outside the string tables. The components that own words, and their table types:

| Component | `labels` type |
| --- | --- |
| `ActionBar` (and `ActionBar.Copy`, `ActionBar.Regenerate` inside it) | `ActionBarLabels` |
| `AttachButton` | `AttachButtonLabels` |
| `Bars` | `PageLabels` |
| `CallBar` | `CallBarLabels` |
| `CodeBlock` | `CodeBlockLabels` |
| `Composer` | `ComposerLabels` |
| `ConfirmDialog`, `Dialogs` | `DialogLabels` |
| `DataTable` | `DataTableLabels` |
| `DiffViewer` | `DiffViewerLabels` |
| `Dropzone`, `UploadList` | `DropzoneLabels` |
| `FileRow`, `FileList` | `FileRowLabels` |
| `HandoffReceipt` | `HandoffReceiptLabels` |
| `Label` | `LabelLabels` |
| `ListSort` | `ListLabels` |
| `Markdown` | `MarkdownLabels` |
| `PasswordInput` | `PasswordInputLabels` |
| `PayloadBlock` | `PayloadBlockLabels` |
| `PendingFiles` | `PendingFilesLabels` |
| `PermissionCard`, `DecisionCard` | `InteractionCardLabels` |
| `Progress` | `ProgressLabels` |
| `ReasoningFold` | `ReasoningFoldLabels` |
| `RecoveryKey` | `RecoveryKeyLabels` |
| `Select` | `SelectLabels` |
| `Spinner` | `SpinnerLabels` |
| `ThreadSkeleton` | `ThreadSkeletonLabels` |
| `Toaster` (and every toast) | `ToastLabels` |
| `ToolCard` | `ToolCardLabels` |
| `UserMessage`, `AssistantMessage` | `MessageLabels` |
| `VoiceIndicator` | `VoiceIndicatorLabels` |

Notes:

- `Field` renders a `Label`, so its "optional" word follows the locale. `Field` has no `labels` prop; to change that word, pair the control with your own `<Label labels={{ optional: … }}>`.
- Many components also keep single-word props from before `labels`, such as `copyLabel`, `cancelLabel` or `streamingLabel`. Where they still exist they win over `labels`. Some are deprecated in favor of `labels` and will be removed in a future major: `DataTable`'s `filterPlaceholder`, `countLabel`, `selectLabel`, `selectAllLabel`, `editLabel` and `clearLabel`; `FileRow`'s `selectLabel`; `FileList`'s `selectedLabel`; `Label`'s `optionalLabel`.
- Some names have no built-in default because only you know the right word: `IconButton`'s `label`, a removable `Chip`'s `removeLabel`, a table row `Toggle`'s `label`, and `confirmLabel` on a confirm.

## How a component declares its words

These are the public building blocks, so your own components can use the same pattern.

```tsx
import { type StringsOf, defineStrings, useStrings } from "@anyknown/ui"

const strings = defineStrings({
  "zh-TW": { close: "關閉", count: (n: number) => `${n} 則` },
  en: { close: "Close", count: (n: number) => `${n} items` },
})

export type ThingLabels = StringsOf<typeof strings>

export function Thing({ labels }: { labels?: Partial<ThingLabels> }) {
  const t = useStrings(strings, labels)
  return (
    <button type="button" aria-label={t.close}>
      {t.count(3)}
    </button>
  )
}
```

- `defineStrings(tables)` declares the words. `"zh-TW"` sets the shape; `en` must have the same keys and types; any other locale may be partial.
- A word is a string, or a function returning a string when it contains a number or a name (`count` above).
- `StringsOf<typeof strings>` is the table type, for the `labels` prop.
- `useStrings(strings, labels)` returns the words for the current locale: that locale's table over `en`, with `labels` over both. An `undefined` value in a partial table or in `labels` means "not set", not "blank".
- `resolveStrings(strings, locale, labels?)` does the same outside React, for example in a toast message built in an event handler or in a test.

## Add a locale

Any locale tag works today: a locale with no table reads English.

To ship words for a new language in a component, add its table to that component's `defineStrings` call. It may be partial; missing words fall back to `en`:

```tsx
import { defineStrings, resolveStrings } from "@anyknown/ui"

const strings = defineStrings({
  "zh-TW": { close: "關閉", count: (n: number) => `${n} 則` },
  en: { close: "Close", count: (n: number) => `${n} items` },
  ja: { close: "閉じる" },
})

resolveStrings(strings, "ja").close // "閉じる"
resolveStrings(strings, "ja").count(3) // "3 items", from en
```

When contributing a locale to the package:

- Add the table to the component's own file, next to `zh-TW` and `en`. There is no central dictionary.
- Use the exact tag your app passes to `LocaleProvider`. Tags are matched exactly: `"ja"` and `"ja-JP"` are different tables.
- Translate the words for their role, not literally. A screen-reader prefix like `success` ends with the punctuation the language uses before the message.

If you only need different words in one app, use `labels` instead of adding a table.

## Raw-literal guard

`src/test/literals.test.ts` scans `src/components` for raw design values that should be tokens: durations like `120ms`, numeric `zIndex`, hex colors, raw `fontSize` values and `@media` breakpoints. It is not about words: it does not check for hard-coded text. A line that must keep a literal says why with `// literal-ok: <reason>`. Existing literals are counted in `src/test/literal-baseline.json`; the test fails when a file goes over its count, and also when it goes under, so the baseline only ever shrinks (`UPDATE_LITERAL_BASELINE=1 pnpm vitest run src/test/literals.test.ts` lowers it).

Built-in words are kept in check by convention instead: new words go through `defineStrings`, as described in the [component conventions](../../src/components/README.md).

## CJK typography

- Latin text uses Figtree (`font.body`, `font.display`) or Geist Mono (`font.mono`). Chinese characters in the same run fall through to Noto Sans TC, which every stack lists right after its Latin font. After that, the body and display stacks try PingFang TC and Microsoft JhengHei; the mono stack goes to the system monospace font.
- Install Noto Sans TC (see [Getting started](./getting-started.md#fonts)) so Chinese renders the same on every platform.
- Noto Sans TC from `@fontsource-variable` or Google Fonts is split into `unicode-range` slices that load only when a character from that slice first appears, which can be long after `document.fonts.ready` has resolved. Textarea auto-grow re-measures on every `loadingdone` event for this reason (see [Text layout](./text-layout.md)). Code of your own that measures text should do the same.
